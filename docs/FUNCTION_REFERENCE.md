# Function and module reference

[Documentation home](README.md) · [Named-function source index](SOURCE_INDEX.md)

This guide explains the main contracts and the modules that own them. The index locates named declarations, including internal helpers. Anonymous event callbacks and class/object methods are read in their containing module; this is not a generated API specification for every JavaScript expression. Inputs described below are internal objects unless an HTTP route is explicitly named. The implementation's validation remains authoritative.

## SCAD → editable settings

| Source / functions | Inputs, behavior and outputs |
| --- | --- |
| [scad-syntax.mjs](../lib/scad-syntax.mjs): `scanScad`, `decodeScadString`, `isComment` | Scans source while distinguishing strings, comments and delimiters. Decodes SCAD escapes. Supplies shared syntax information; does not execute source. Nesting is bounded. |
| [parser.mjs](../lib/parser.mjs): `parseLiteral` | Reads supported literal values; expressions are not executed as JavaScript. |
| `parseScadDocument`, `parseScadParameters` | Produce parameter metadata, assignments, components and diagnostics; the latter returns only parameters. Scope and last global assignment decide which values can become controls. Customizer hints constrain presentation. |
| `valueToScad` | Serializes validated typed parameter values back into SCAD syntax with string escaping and array handling. Keep this boundary instead of interpolating arbitrary values into definitions. |
| [font-defaults.mjs](../lib/font-defaults.mjs): `applyFontDefaultsToSource`, `defaultFontParameters` | Normalize supported literal font defaults and parameter metadata to bundled Baloo. Computed expressions stay intact. |
| [scad-object-selectors.mjs](../lib/scad-object-selectors.mjs): `inferDesignSelector`, `objectSelectorDefinition` | Infer supported selector conventions from metadata and build a validated definition for selecting a design. |
| [server.mjs](../server.mjs): `detectObjects`, `modelInfoFromSource` | Combine parsed values, manifests, selectors and part capabilities into model metadata shared by workspace and Instant generation. |
| `normalizeValues`, `trustedInternalDefinitions`, `previewFacetCap` | Validate overrides and internal selector definitions; calculate preview-only facet reduction. They protect the boundary between UI values and render input. |

A new parser feature must preserve computed SCAD semantics and diagnostics. Do not expose a variable merely because a regular expression finds an equals sign.

## Rendering and lifetime

| Source / functions | Responsibilities |
| --- | --- |
| [server.mjs](../server.mjs): `findOpenSCAD`, `probeRemoteRenderer`, `renderCapacityFor` | Discover a usable engine/remote renderer and its advertised concurrency. |
| `renderModel(values, format, extra)` | Central validation/render/cache/scheduler boundary. Resolves source and metadata, applies definitions, handles independent solid-part requests and chooses the renderer. Returns generated bytes or a validation/runtime error. |
| `remoteRendererRequest`, `renderAbortSignal` | Send private render requests and tie cancellation to client disconnects. |
| [render-scheduler.mjs](../lib/render-scheduler.mjs): `RenderScheduler`, `SharedRenders` | Bound weighted jobs and queue size; share matching in-flight work. Preserve cancellation ownership when multiple consumers share a render. |
| [parallel-work.mjs](../lib/parallel-work.mjs): `parallelWork` | Run items up to a concurrency limit with stable result order and coordinated cancellation. Wait for sibling work before caller cleanup. |
| [render-cache.mjs](../lib/render-cache.mjs): `DiskRenderCache` | Manage bounded disk render results. Cache correctness depends on complete request identity and dependency handling in the caller. |
| [render-resources.mjs](../lib/render-resources.mjs): `localVmResources`, `workerCapacity` | Derive VM size and worker capacity from measured resources and per-worker budgets. Explicit operator limits can override defaults. |
| [renderer-containers.mjs](../lib/renderer-containers.mjs): `containerArguments`, `ContainerRenderer` | Assemble hardened Docker arguments, initialize/recover the worker scope, schedule jobs, collect output and remove workers. |
| [renderer-runtime.mjs](../lib/renderer-runtime.mjs): `capabilities`, `render`, `thumbnail` | Check runtime readiness; materialize a job; invoke bounded native OpenSCAD/image operations; read output. `runProcess` owns subprocess timeout/error behavior. |
| [renderer-output.mjs](../lib/renderer-output.mjs): `validateRendererOutput` | Reject oversized or invalid output before the trusted manager returns it. |
| [renderer-worker.mjs](../renderer-worker.mjs) | Dispatch a single operation inside the disposable execution environment. |
| [renderer-service.mjs](../renderer-service.mjs) | Expose private GET `/healthz`, POST `/render`, POST `/thumbnail`; authenticate private requests and propagate cancellation. |

## Geometry → colored archive → history

| Source / functions | Responsibilities |
| --- | --- |
| [solid-parts.mjs](../lib/solid-parts.mjs): `supportsSolidParts`, `renderSolidParts` | Conservatively recognize supported separate-part exports. Render each selected part via the callback, preserve closed meshes and colors, pack the intermediate geometry and dispose temporary geometry. The callback must still use global scheduling. |
| [solid-3mf.js](../public/solid-3mf.js): `readSolid3mf` | Unpack 3MF/XML into geometry and optional color metadata for downstream transforms and packing. Browser DOM parsing is default; Node callers inject an XML parser. |
| [export-geometry.js](../public/export-geometry.js): `geometryForPrint`, `placeObjectsOnBed` | Apply print transforms and normalize bed placement without modifying the source model definition. |
| [export-recipe.js](../public/export-recipe.js): `recipeForExport` | Convert selected plans, requests, profile, printer, title, scope and workflow into a replayable recipe. |
| [export-history.mjs](../lib/export-history.mjs): `validateRecipe` | Validate recipe shape, limits, object contributions, matrices and settings before generation. |
| `renderExportRecipe(recipe, options)` | Deduplicate render requests, render with bounded concurrency, transform contributions (including mirrored winding), assign palettes, pack selected populated plates, estimate filament and optionally rasterize the preview. Returns archive, estimate, preview, plate IDs, count and fingerprint; disposes geometry in `finally`. |
| `archiveFingerprint` | Hash archive content independently of incidental ZIP packaging details, enabling regenerated-content comparisons. |
| `createExportHistory(db, options)` | Initialize snapshot/event persistence and owner-scoped recording/replay operations. Freeze resolved inputs/runtime, reuse identical snapshot previews and reject mismatched replay. Generated archive bytes are returned, not stored as the history record. |
| [export-preview.mjs](../lib/export-preview.mjs): `exportPreview` | Rasterize the final plate geometry into a saved PNG. This is distinct from workspace WebP thumbnails. |
| [core-3mf.js](../public/core-3mf.js): `packCore3mf`, `packBambuMultiPlate3mf` | Serialize meshes, palette/filament assignments, object settings, compatible template metadata and attachments into 3MF ZIP structure. Multi-plate packing carries plate definitions. `packZip` and `utf8` provide archive utilities. |
| [bambu-export-profile.mjs](../lib/bambu-export-profile.mjs): `bambuVendorDefaults`, `bambuExportProfile` | Resolve local preset inheritance and compatible machine/material/nozzle templates; validate and apply permitted process settings. Missing vendor data must not cause fabricated printer metadata. |
| [filament-estimate.js](../public/filament-estimate.js): `meshMeasures`, `estimateFilament` | Measure triangle geometry, approximate shell/infill mass and estimate color-change material from geometry plus saved settings. Output is pre-slice, approximate and excludes several real-print costs. |
| [export-history-ui.js](../public/export-history-ui.js): `initExportHistory`, `downloadRecordedExport`, `grams` | Open/list history, show frozen previews and nozzle comparison, request recorded downloads/replays and format approximate grams. |
| [export-worker.js](../public/export-worker.js) | Handle worker messages for suitable packing/color-optimization tasks outside the main UI thread. |

Export recipes containing separate parts carry `colorExportVersion: 3` in the current implementation. Older incompatible recipes are refused rather than silently assigned new colors. Changing replay semantics requires explicit compatibility handling and a regression test.

## Layout, settings and variants

| Module | How it works |
| --- | --- |
| [origin-layout.js](../public/origin-layout.js): `originLayout` | Check untouched design bounds for shared overlap at the SCAD origin and calculate nonoverlapping bed placements. `autoPositionOriginDesigns` in the editor applies this once per imported source and records its inverse without changing generation inputs. |
| [history-shortcuts.js](../public/history-shortcuts.js): `historyShortcutAction`, `HeldHistoryShortcut` | Recognize Shift+Enter and Ctrl+R for object undo/redo, and Ctrl+Enter for one color-arrangement undo (including keypad Enter); repeat completed history steps with no async backlog and cancel on release/focus loss. Default timer wrappers retain the browser Window receiver. Editor `rememberObjectEdit` bounds and branches history; `replayObjectEdit`, `undoObjectEdit` and `redoObjectEdit` apply inverse object edits. |
| [plate-packing.js](../public/plate-packing.js): `arrangeObjects` | Deterministically pack object bounds into supported printer beds, accounting for gaps, rotations and forbidden regions. `arrangeObjects` accepts optional ordering/rotation preferences for budget trials; defaults preserve existing layouts. `minimumPackingPlates` supplies a conservative area lower bound for early stopping. |
| [workflow-store.js](../public/workflow-store.js) | `compatiblePresetValues` filters saved values; `evaluatePresetStack` resolves selected presets; `cartesianPresetCombinations` expands combinations; `distributeObjectIds` assigns groups to bounded plate IDs. Persistent IDs and keyboard helpers support editor state. |
| [print-settings-schema.js](../public/print-settings-schema.js) | `PRINTERS` and `PRINT_SETTINGS_GROUPS` are shared UI/export definitions. `createDefaultProfile` constructs defaults; `migratePrintSettings` normalizes older settings. |
| [sku-model.js](../public/sku-model.js) | `validateOverrides` checks design/process changes; `variantDifferences` describes changes; `resolveSkuVariant` applies a variant to a saved SKU; `captureObjectSnapshot` freezes object inputs. |
| [production-variants.mjs](../lib/production-variants.mjs): `createVariantStore` | Persist owner-scoped SKU variants with storage and validation hooks. |
| [object-plate-location.js](../public/object-plate-location.js) | Shared object/plate location logic used by editor organization. |
| [color-optimization.js](../public/color-optimization.js) | `analyzeColorLayers` derives layer occupancy; `combineColorRuns` combines analyses; `estimateSwaps` estimates transitions; `packColorGroups` keeps the existing grouping algorithm or delegates to `packColorBudget` for a workspace-wide maximum. Budget planning caches bounded pair merges and compares valid compact packing, preferring fewer plates within the cap. `colorOptimizationSettings` validates the optional integer limit. `ColorAnalysisCache` reuses analysis by identity. |
| [color-budget-ui.js](../public/color-budget-ui.js) | `initColorBudgetUi` shares the workspace/Instant popover and opens pending settings, validates a maximum, closes immediately on Apply and returns focus to the workspace. Cancel/Escape/outside dismissal discard drafts. Saved settings commit in the editor only after success and the stale-state check. `undoWorkspaceColorArrangement` restores the latest arrangement and disables its checkbox while preserving redo. |
| [workspace-color-optimization.js](../public/workspace-color-optimization.js) | `optimizeWorkspacePlates` analyzes and arranges workspace exports; `optimizedEditorOffset` maps optimization transforms back into editor coordinates. |

## UI entrypoints

- [app.js](../public/app.js): main editor state, parameter controls, Three.js scene, selection/transforms, workspace saving, print controls, account/settings dialogs and export orchestration. `openExportMenu` and `downloadGeneric3mf` clear stale export errors through `clearExportError` before retry.
- [projects.js](../public/projects.js): project/Instant library and export-history entrypoint.
- [instant.js](../public/instant.js): upload, mapping, run progress, download and workspace conversion UI.
- [configure.js](../public/configure.js): public approved-parameter configurator; collect values and submit jobs.
- [welcome.js](../public/welcome.js): login/signup and verification UI.
- [production-dashboard.js](../public/production-dashboard.js): Advanced/production integration, saved values and variants; contains additional legacy production support.
- [startup-errors.js](../public/startup-errors.js): expose startup failures in the browser.

HTML files define controls/dialog containers; corresponding CSS defines appearance. Read both when changing DOM IDs or accessibility behavior.

## Server storage and route ownership

All application routes are implemented in [server.mjs](../server.mjs), with stores delegated to `lib/`. This is an internal route map, not a stable external SDK contract. Consult handler validation and caller code for exact JSON fields.

| Route family | Ownership / implementation |
| --- | --- |
| `/healthz`, `/api/auth/session`, `/api/auth/*` | Health and account entry. `createAccount`, `authenticateAccount`, `derivePassword`, challenge helpers, `createSession` and `requestSession` implement password/email/session flows. |
| `/api/account/*` | Settings, preferences, password/email verification, sessions, activity, quota and data operations. Sensitive actions reauthenticate. |
| `/api/workspaces` and `/:id` | Owner-scoped list/create/read/save/delete. `sanitizeWorkspaceData`, `createWorkspace`, `saveWorkspace`, `getWorkspace` validate/persist state. |
| Workspace `/revisions`, `/restore`, `/library`, `/bootstrap`, `/preview` | `storeWorkspaceRevision`/`restoreWorkspaceRevision`, library options, combined metadata and scheduled preview generation. |
| `/api/model`, `/api/models/upload`, `/api/fonts*` | Source metadata/upload and project font catalog; `modelInfo`, `storeUploadedModels`, `getLocalFontCatalog`. |
| POST `/api/render`, `/api/render-object`, `/api/export` | Validated render/export calls using `renderModel`; format and preview behavior depend on the endpoint/query. |
| GET/POST `/api/export-history`, snapshot `/preview`, POST `/again` | `createExportHistory` recording, listing, images and verified replay. |
| `/api/export-profile`, `/api/bambu-defaults`, `/api/print-profile`, `/api/print-profiles` | Profile sanitization, persistence/selection and Bambu template resolution. |
| `/api/instants` and setup `/files`, `/runs`, `/cancel`, `/convert`, `/result` | Instant store lifecycle and downloads. |
| `/api/production/*` | SKUs, variants, job batches, resolution, configurators, templates, components, calibrations, webhooks and diff. `createProductionJobFromSku`, `validateProductionRules`, snapshot/diff helpers enforce saved production context. |
| `/api/public/configurator*`, `/api/webhooks/order` | Deliberately public entry flows use configurator constraints or webhook credentials instead of trusting arbitrary owner IDs. |

Request helpers enforce host/origin/proxy policy, body bounds, rate limits and error formatting. Static serving must not expose durable data or credentials. Account storage checks and revision limits belong to write operations, not only UI warnings.
